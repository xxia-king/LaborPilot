# 工作图节点契约

每个节点必须具有输入、产物、完成条件、责任主体和失败去向。机器可读定义位于 `workflow/graph.json`。

| 节点 | 必要输入 | 主产物 | 完成条件 | 责任主体 |
|---|---|---|---|---|
| task_intake | 用户发起办案请求 | 任务目的、代理立场、案件阶段和地域确认记录 | 用户已确认具体任务、劳动者／用人单位立场及程序阶段 | 任务确认 Skill／用户 |
| material_ingestion | 原始文件 | `.casework/materials/` 中的哈希、页码、文字层检测和派生索引 | 至少一份具有 `material_id`、来源路径和 SHA-256 的可追溯材料，或有结构化用户确认豁免 | 材料接入 Skill |
| intake | 已登记材料、代理立场（可待确认） | 更新《案件研判报告》的案件画像与时间轴，并更新《行动清单》 | 至少一条具有 `fact_id` 的结构化事实，或有结构化用户确认豁免 | 案件接入 Skill |
| issue_analysis | 接案结果 | 更新《案件研判报告》的问题树与请求／抗辩矩阵 | 至少一个具有 `issue_id` 的争点，并按案件需要覆盖要件、备选路径和对方最强观点；无实体争点时须有结构化用户确认豁免 | 争点 Skill |
| evidence_analysis | 要件与材料 | 更新《案件研判报告》的证据矩阵和《行动清单》 | 至少一条具有 `evidence_id` 的证据、缺口或举证责任记录，或有结构化用户确认豁免 | 证据 Skill |
| authority_research | 结构化检索问题 | 更新《案件研判报告》的已验证法源与浙江口径 | 至少一条具有 `rule_id`、核验状态、法规和条文锚点的法源，或有结构化用户确认豁免 | 法源 Skill |
| claims_procedure | 请求、输入数据、程序事件 | 更新《案件研判报告》的金额与程序章节，计算中间件进入 `.casework/calculations/` | 至少一个具有 `claim_id` 的请求／抗辩；金额型项目关联 `calculation_id`，或有结构化用户确认豁免 | 金额程序 Skill |
| strategy_approval | 前述全部底稿 | 起草授权与临时策略记录 | 代理立场、阶段和请求文书已唯一确定；无未决的互斥策略。用户的明确起草请求可直接形成“律师复核初稿”授权 | 律师／用户请求 |
| drafting | 已审批策略与已验证底稿 | 律师复核初稿 | 初稿真实存在、已登记到 `artifacts`，且本次转换通过 `--output-artifact` 关联；不得豁免 | 文书 Skill |
| validation | 案件状态与待验证产物 | `.casework/validation/` 中含 `status` 和 `findings` 的 JSON 独立验证报告，可附人读 Markdown | 全部必需验证类型有真实 JSON 报告；正常通过时均为 `pass`，升级律师时可为 `escalate`；不得仅以命令行状态自报，不得豁免 | 验证 Skill／程序 |
| lawyer_approval | 已通过验证的初稿 | 审批记录 | 律师明示通过或退回 | 律师 |
| stage_close | 审批结果与阶段成果 | 就地更新的单一案件状态 | 事件、产物、期限和下一步已回写 | 总控 Skill |

## 转换结果

- `pass`：满足完成条件，进入下游节点。
- `return`：产物可修复，返回指定上游节点。
- `pause`：缺少用户信息、原始材料或外部检索结果，保存检查点后暂停。
- `escalate`：存在高风险、冲突指令或不可由系统决定的策略，升级律师。
- `blocked`：状态或产物损坏，在修复前不允许继续。

`record-waiver` 只适用于机器图中明确标记 `waiver_allowed` 的条件，且必须记录具体理由、确认人和确认时间。它用于表示真实任务范围不包含某类材料或记录，不是跳过尚未完成工作的快捷方式。
