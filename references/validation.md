# 独立验证规则

## 机器报告契约

- `record-validation --report` 只接受 JSON object，顶层必须包含 `status` 和 `findings` 数组。
- 验证结论为 `pass` 或 `escalate` 时必须提供上述 JSON 报告；仅在命令行自报状态而不附报告会被拒绝。
- Markdown 可作人读附件，但不得代替 JSON 状态记录。
- `findings` 至少保留问题 ID、严重程度、描述、处理方式和受影响节点。

## 确定性检查

- `case_state` 必填字段、ID 唯一性和引用完整性。
- 每个 `supported` 事实至少有一个材料来源。
- 争点路由按案件需要动态召回并覆盖相关争点；不输出完整知识卡正文、原始字段、内部卡号或案由门卡。
- `VERSION`、Plugin 清单、根 Skill、子 Skill 与 `CHANGELOG.md` 版本一致，`python3 scripts/sync_version.py --check` 通过。
- 每个请求／抗辩关联争点、事实、证据和法源。
- 金额型请求关联已验证计算记录。
- 引用法源具有文档和条文锚点，废止或异常项未被静默采用。
- 有程序事件时存在对应期限及核验状态。
- 产物具有版本、哈希、生成者和生成时间。
- 原始材料具有来源哈希和页码定位；OCR 或其他派生结果具有本地路径与复核状态。
- 处理任何案件材料前，`task_context`、`representation` 和 `stage` 均已获得用户确认。
- 当前节点在工作图中存在，且没有尚未修复的上游 `return`、`failed`、`paused` 或 `escalated` 结果。
- `representation=undetermined` 或 `stage=undetermined` 时只能停留在 `task_intake`，不得处理材料或进入实体节点。
- 起草节点前存在起草授权与临时策略记录；用户明确请求特定文书时可以此作为授权，但互斥立场未决时仍必须暂停。交付前存在独立验证和律师审批。

## 对抗性检查

1. 将我方最重要结论作为待证命题，寻找能推翻它的事实、证据和法律规则。
2. 检查对方最强观点是否被弱化或遗漏。
3. 检查主体、关系性质、仲裁前置、管辖、时效、终局裁决及救济路径。
4. 检查结论是否将当事人陈述或对方主张写成已证事实。
5. 说明当前分析最可能失败的边界条件。

## 结果严重程度

- `blocker`：不得进入下一节点。
- `high`：原则上返回修复或升级律师。
- `medium`：允许带显式风险进入审批。
- `low`：记录后可继续。
