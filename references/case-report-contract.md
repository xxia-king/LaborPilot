# 《案件研判报告》结构契约

《案件研判报告》是承办律师用来作决定的内部分析文件，不提交仲裁委或法院，不生成最终提交版。生成器按本契约的固定骨架渲染，转换前由 `scripts/report_lint.py` 校验；语体规则见[书面语体规范](writing-style.md)。

## 读者与目的

读者是承办律师，必要时转给客户法务。报告首页要让读者作出四项决定：

1. 是否继续当前程序，目标是改判、调解还是和解。
2. 主要依靠哪些理由，放弃哪些理由。
3. 近期必须办理哪些事项。
4. 需要支付或可以获得的金额范围。

报告按这四项决定组织，不按工作图节点组织。各节点把结构化结果写入 `case_state`；`scripts/build_report_input.py` 从状态生成报告输入脚手架，起草者补写论证后由生成器一次渲染。节点不得各自改写报告正文。

## 固定骨架

| 部分 | 内容 | 输入字段 |
|---|---|---|
| 一、决策摘要 | 结论段（结论在前，写明把握程度）；可能结果表；需要立即办理的事项及期限 | `决策摘要.结论`、`决策摘要.可能结果`、`决策摘要.紧急事项` |
| 二、争点分析 | 争点一览表（可选）；每个争点一个二级标题，下设一段或数段 | `争点[].标题`、`争点[].段落`、`争点[].一览` |
| 三、金额与期限 | 金额表；期限段落 | `金额`、`期限` |
| 四、策略与建议 | 调解、和解与后续程序安排 | `策略` |
| 附件 | 法律依据原文；判决要点摘录、类案及核验状态等其他材料 | `附件.法律依据`、`附件.其他` |

- 某部分没有内容时省略，编号自动顺延。
- 正文（附件以外）默认不超过 4000 字，可用 `report.篇幅上限` 或 `--report-char-limit` 调整；决策摘要默认不超过 900 字，可用 `report.首页上限` 调整。

## 推理规则

1. **论点清单先行。** 动笔前在 `论点清单` 中列出全部论点，并为每个论点指定唯一位置：`决策摘要`、某个争点的 `id`、`金额与期限` 或 `策略与建议`。缺少论点清单、同一论点重复登记或位置不存在的，生成器拒绝生成。
2. **一个论点只在一处完整论述。** 其他部分需要时只引结论，或写明“见第二部分（一）”，不重述理由。
3. **一段只讲一个命题。** 段首句就是该段结论，其余句子为它服务。
4. **争点段落按判决式顺序写。** 依次为结论及把握程度、规范依据、本案事实与证据现状、对方最强观点及回应、判断及会改变判断的条件。不写“大前提”“小前提”等标签，推理顺序由句序和“依据”“本案中”“然而”“因此”等连接词表达。
5. **展开深度与争议程度相当。** 无争议的构成要件一句带过。规范本身有争议的，先论证规范（法律解释、指导性案例的适用与区分）；事实有争议的，按待证事实、证据、证明力、是否达到证明标准的顺序写。
6. **推理只向前。** 前文为后文提供前提，后文承接前文，不回头重讲。首页每一句结论都能在争点分析中找到唯一出处。
7. **结论不夸大确定性。** 可能性判断属于经验判断，写明依据；未核实之处在当句使用 `【待确认：……】`。

## 内容放置

| 内容 | 位置 |
|---|---|
| 法律条文原文 | 附件；正文写法律全称加条款项序号 |
| 裁判文书原文 | 正文只写与争点有关的认定；摘录放附件 |
| 事实时间轴、材料清单 | `.casework/intake/`；正文只引用与争点有关的关键事实 |
| 待补材料、客户询问、补证行动 | 《待补材料与行动清单》；决策摘要只列最急的几项 |
| 版本说明、检索与核验过程 | `.casework/` 和文档属性；不进入正文 |
| 与本案结果无关的建议（如企业制度整改） | 另行出具，不进入报告 |

## 表格

只使用三种标准表，列宽由版式脚本按表头确定：

| 表 | 表头 |
|---|---|
| 可能结果 | 可能结果、可能性、金额影响 |
| 争点一览 | 争点、我方主要理由、主要障碍、评估 |
| 金额 | 项目、金额（元）、说明 |

每格写一个规范短语，不超过 40 字，可以省略主语，不写论证理由；不用“败”“中低”这类需要读者猜测的标签。

## 复核与修改

- 对抗验证和律师复核的意见，改进对应争点的原段落；不在段后追加“但必须清楚”“另需评估”“另有一处”这类补丁段。
- 修改后重新生成新版本（`--version`），不覆盖旧版本。新版本正文比上一版长的，在 `.casework/drafting/` 记录新增内容及理由。

## 生成与校验

```bash
# 从案件状态生成输入脚手架：预填阶段、立场、已复核争点、金额台账、时效截止日和已采用法条全文；不覆盖已有文件
python3 scripts/build_report_input.py --state <case-root>/.casework/case_state.json --case-name <案件名称>

# 起草者补写全部【待撰写】处和论点清单后，先校验写作，再生成（生成器内部也会再校验一次）
python3 scripts/report_lint.py --input <case-root>/.casework/drafting/report_input.json
python3 scripts/generate_docs.py --case <case-root>/.casework/drafting/report_input.json --output <case-root> --types 研判报告 --strict

# 检查既有报告（包括旧版本或其他工具生成的 DOCX）
python3 scripts/report_lint.py --docx <报告.docx>
```

脚手架中的金额、期限和附件法条来自已复核的案件状态，不得手工改写数值或条文；`_写作参考` 字段只供起草，不进入报告。仍有“【待撰写】”占位或论点清单为空时，写作校验阻断生成。写作校验结果为 `blocked` 时不生成 DOCX，`.casework/drafting/` 中保留 `_写作校验.json` 供修改；`warn` 的提示项应在律师复核前逐项处理或说明理由。
